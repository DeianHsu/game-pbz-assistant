# 影之刃零 · 行前检查

**版本 1.1.0** · Windows x64 · Steam 版

从本机存档查看支线风险、当前任务目标、地图收集、全收集品和成就。在打首领或推进主线前，可以先检查有没有该交的任务、尚未领取的奖励，或等以后才能回访的收集点。

## 下载与使用

1. 下载 `PBZ-Quest-Guard-1.1.0-native-win-x64.exe` 即可使用。[GitHub v1.1.0 发行页](https://github.com/DeianHsu/game-pbz-assistant/releases/tag/v1.1.0)
2. 确认已安装 Steam 版《影之刃零》，并在游戏内至少保存过一次。双击 exe，工具会自动查找 Steam 库和存档，默认打开“继续游戏”对应的槽位。也可以在顶部切换账号和槽位。
3. 游戏再次保存后，点击 **重新读取存档** 或按 **F5**。界面显示的是所选槽位最后一次写入磁盘的进度。

程序使用 64 位 Windows 的系统组件 .NET Framework 4，读取时无需联网。应用直接打开原生窗口，无需安装、解包或启动后台服务。工具只读取本机游戏文件和存档，不修改或上传存档。

## 缺失与不足

- **任务和剧情覆盖有限。** 85 项检查是一份风险清单，并未覆盖每条支线、所有对话选项和全部不可逆节点。部分截止事件来自攻略，尚未逐项实机复现。陈柱选项等存在资料分歧的内容会提示现场核对。真结局相关条目是保守检查清单。
- **获取路线和门锁尚未补齐。** 部分收集品目前只有地区、最近铃铛或物品记录，具体门锁和触发点仍需游戏内确认。一个地图分组缺少原生中文名，会保留原始标识。
- **拾取点受场景和存档记录限制。** 金额按所选周目显示，有多种奖励数量的点位会列出可识别的候选值。吊挂物被击落后，存档有时只能确认击落，需要回游戏确认是否已经拾取。
- **存档只能反映已保存的变化。** 刚触发的事件要等游戏保存后刷新。限时对话和战斗中的解脱时机仍需现场留意。“存档未记录”表示缺少对应证据，明确失败以游戏日志或事件为准。
- **成就进度和前置使用不同记录。** 解锁状态来自本机账号，当前可做情况根据所选槽位的剧情、任务和装备判断。可读取的计数或等级会显示在进度栏。完成步骤尚未逐项在游戏内触发验证。
- **版本适配范围明确。** 当前支持 Windows x64 上的 Steam 版和上述两个游戏构建。新构建需要重新核对存档格式与游戏资源后才能加入支持。原生版已用真实槽位和参考实现对照，尚未逐章实机走通所有路线。

## 常见问题

- **找不到存档。** 确认游戏由 Steam 安装，进入游戏并完成一次保存后按 F5。
- **显示游戏版本未经验证。** Steam 更新可能改变存档和资源格式，请查看是否有更新的工具发行版。
- **进度跟游戏里不一样。** 检查顶部账号、槽位和保存时间。选择旧的手动槽位时，任务和地图会回到那个槽位的进度，账号成就仍使用当前本地解锁记录。
- **下载后出现安全提示。** 发行 exe 当前未签名。若软件将文件隔离，反馈时请附检测名称和文件路径。

## 从源码构建

准备 Zig 0.15.2、Windows .NET Framework 的 C# 编译器和 Node.js。Node.js 用于构建时生成攻略数据，以及运行测试。

```powershell
powershell -ExecutionPolicy Bypass -File native/build.ps1 -Zig "C:\path\to\zig.exe"
npm ci
npm test
node native/verify.mjs
```

发行文件和 SHA-256 校验文件生成在 `release/`。最后一条命令需要本机有受支持的游戏和存档，会对照原生程序和参考实现，并检查七个页面的数据加载。

- `native/` 保存原生窗口、游戏与存档读取、状态判断、构建脚本和解压源码。
- `reference/` 保存构建时使用的攻略数据及开发用参考实现。
- `test/` 保存回归测试。
